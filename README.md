# OPMChord 1.2.3

YM2151（OPM）の1chに3個または4個のキャリアを割り当てて、コードを演奏するWindows用ツールです。同梱の`data/YM2151_ALG_5_6_7_Code_4MHz.xlsx`から抽出した739件のKC/KF・ML/DT1/DT2をそのまま使用します。

同梱EXE（本体x64・X68Sound補助x86）はZig 0.13.0でクロスビルドしています。VS2022でビルドする場合は同梱ソースと`build_vs2022.bat`を使用してください。VS2022での実ビルドは未検証です。

## 起動

ZIPを展開し、`bin/OPMChord.exe`を実行してください。Independent OPM 0.13 x64 DLLを同梱しています。PythonやVisual Studioは実行時に不要です。設定を保存できる場所に展開してください。

出力は毎回Independent OPM、音色はALG5、コードはALG5に保存した種類で開始します（同梱設定ではMajor）。ウインドウは約1300×820ピクセルです。

## 音色編集

ALG5・ALG6・ALG7の3音色を同時に表示します。`ALG 5(,)`／`ALG 6(.)`／`ALG 7(/)`ボタンで演奏音色を選択してください。数値欄に入力すると、選択音色の発音中のチャンネルにも即座に反映します。キャリアのML/DT1/DT2は暗転し編集不可です。選択音色には最後に実際に発音したコードの値を表示します。

表のC1～C3はALG5/6のOP2～OP4、C1～C4はALG7のOP1～OP4へ割り当てます。OP番号はレジスタブロック（+0、+8、+16、+24）の順序です。表の「C1」はキャリア番号であり、OPMのオペレータ呼称C1との同一性は意味しません。

ALG7の3和音はOP1～OP3を使用し、OP4をキーオンマスクで除外します。OP4のTLは変更しません。ALG5のOP1はML/DT1/DT2を編集できます。ALG6のOP1はOP2と同じML/DT1/DT2へ自動設定し、編集不可です。

画面のパラメータ順は AR / DR / SR / RR / SL / TL / KS / ML / DT1 / DT2 / AM です。設定ファイルのD1R、D2R、D1Lはそれぞれ画面のDR、SR、SLに相当し、従来の設定を読み込めます。選択された音色・コードボタンは青色になります。

数値欄にフォーカスがあるときはPageUp/PageDownで値を1ずつ変更し、上下限で停止します。オクターブは変更しません。アルファベットキーは数値欄へ入力されず、フォーカスを保持して対応する鍵盤を演奏します。数字は数値入力に使用します。

| 欄 | 範囲・意味 |
|---|---|
| ML | 0～15。0は0.5倍 |
| DT1 | 0～7。レジスタの符号を含む生値 |
| DT2 | 0～3。レジスタ上位2bitの値 |
| TL | 0～127。大きいほど小音量 |
| KS | 0～3。キースケーリング |
| AR / DR / SR | 各0～31。アタック／第1・第2減衰 |
| SL / RR | 各0～15。第1減衰レベル／リリース |
| AM | 0～1。振幅変調の適用 |
| FB / PAN | 0～7／0～3。PAN: 0=無音、1=左、2=右、3=両側 |
| PMS / AMS | 0～7／0～3。音程／振幅LFO感度 |
| LFO Freq / AMD / PMD / Wave | 0～255／0～127／0～127／0～3 |

初期音色は持続音向けです。ALG5は3キャリアがOP1によって変調され、ALG6は変調された1キャリアと独立した2キャリア、ALG7は独立したキャリアで構成されます。

設定の最後の変更から2秒経過すると`bin/OPMChord.ini`へ自動保存し、次回起動時に読み込みます。ALG5／6／7ごとにコード種類も記憶します。表による一時的なキャリア値で元音色を上書き保存しません。不正な値は適用されず、フォーカスを移すと直前の有効な値に戻ります。

## 編集欄の移動とALG切り替え

LFOを含む編集欄で上下左右のカーソルキーを押すと、隣接する編集可能な欄へ移動します。暗転した欄は飛ばします。左右は同じ行、上下は次の行の横位置が最も近い欄へ移動し、端では反対側へ戻ります。移動先の文字列は全選択します。

キーボードの`,`でALG5、`.`でALG6、`/`でALG7を選びます。数値欄の編集中も有効です。テンキーの小数点は従来どおりminorを選ぶキーで、通常のピリオドキーとは区別します。

## チャンネルディレイ

画面下部のDelayでOFFまたは1～8の保存パターンを選びます。各パターンは独立した設定を持ち、8パターンの内容は全音色で共有します。OFF／1～8の選択はALGごとに記憶・保存し、音色切り替え時に復帰します。同梱設定はALG5=Delay 2、ALG6=Delay 7、ALG7=Delay 2です。旧設定にALG別の選択がない場合は、従来の共通選択を引き継ぎます。最初の演奏可能な入力からFM1と追加チャンネルを発音します。以後は最後に押した演奏可能な鍵へキーオンを維持したまま音程を変更します。その鍵を離すと、残る鍵のうち最後に押した鍵に戻ります。全て離すとFM1をキーオフし、追加chはそのキーオフを各chの遅延時間後に再現します。キーオン・レガートの音程変更・キーオフを記録して遅延再生するため、短い入力も元と同じ長さで鳴ります。次の入力で以前のディレイ演奏を取り消しません。Esc／All notes offでは遅延予約も含めて解除します。範囲外の入力とMIDI9～16は表示のみです。

| 設定 | 内容 |
|---|---|
| Extra ch | 追加チャンネル数1～7。FM1を含め合計2～8ch |
| Delay / ch | チャンネルごとの追加遅延。0～10000ミリ秒。FM1=0、FM2=1倍、FM3=2倍… |
| KF / ch | KFレジスタ値の加減算。−252～252。各chに番号×設定値を加算し、0～252へ制限。下位2bitは無効なので4単位で設定すると1/64半音ずつ変化。KCは変更しません |
| TL / ch | 追加chごとの音量減衰量0～127。キャリアのTLにch番号×設定値を加算し127に制限（1単位=0.75dB）。元音色のTLは保持します |
| Pan mode | 0=各chともパン列の先頭から開始、1=各chで先頭位置を1つずつずらす |
| Pan sequence | 0～3を連続して入力。配布時の値はパターンごとの設定を参照してください。3=Center、1=Left、2=Right、0=OFF。末尾から先頭へ戻ります |
| Pan interval | 次のパンへ切り替える間隔。0～10000ミリ秒。0は切り替えず固定 |

例えばPan mode=1、Pan sequence=312なら、FM1・FM2・FM3・FM4の初期パンは3・1・2・3です。各chのパン巡回はそのchの発音時を起点にします。パン0は出力を止める設定で、エンベロープ自体は継続します。

コード変更時は押されている鍵で再発音します。ディレイ設定やパターンの変更時は現在の発音を解除します。設定は自動保存されます。配布時の音色・LFO・ディレイ8パターンは、同梱の`bin/OPMChord.ini`で定義しています。

発音とパン切り替えはWindowsタイマーで制御し、実際のタイミングにはWindowsのスケジューリングによる誤差があります。

## コード選択

| コード | テンキー | 発音可能な根音（MIDI番号） |
|---|---|---|
| Major | 0 | B1～C8（35～108） |
| minor | 小数点 | A♯1～C8（34～108） |
| dim | 1 | C1～C8（24～108） |
| aug | 2 | B1～C8（35～108） |
| sus4 | 3 | B1～C8（35～108） |
| 7 | 4 | B1～C8（35～108） |
| maj7 | 5 | B1～C8（35～108） |
| m7 | 6 | D♯2～C8（39～108） |
| m7b5 | 7 | D♯2～C8（39～108） |
| dim7 | 8 | E2～C8（40～108） |

NumLockをONにしてください。上段の数字キーは別オクターブの演奏に使います。ALG5/6では4和音のボタンが暗転します。ALGを切り替えるとその音色に記憶したコードへ戻ります。コード変更時はPC／マウス／MIDIの押されている鍵を保持して、新しいコードで再発音します。新しいコードで範囲外になる鍵は入力表示のみになります。音色切り替え時は発音を解除します。

## 鍵盤・PCキーボード

PageUp/PageDownで内部オクターブ0～8を変更します。MIDI番号60をC4とする表記です。オクターブ変更時はPC入力を解除します。

| 半音位置 | C | C♯ | D | D♯ | E | F | F♯ | G | G♯ | A | A♯ | B |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 現オクターブ | Z | S | X | D | C | V | G | B | H | N | J | M |
| 1つ上 | W | 3 | E | 4 | R | T | 6 | Y | 7 | U | 8 | I |

最大8個のコードを空いているFMチャンネルへ割り付けます。9個目は鍵盤表示のみで、発音中の音を奪いません。キーリピートでは再発音しません。一般的なPCキーボードには同時押し検出の制限があるため、組み合わせによって8キーを検出できない場合があります。

数値欄の編集中もアルファベットキーで演奏できます。上段数字を使った黒鍵の演奏は、数値欄の外へフォーカスを戻して使用してください。マウスでも鍵盤を押して演奏でき、押したまま移動できます。アプリが非アクティブになるとPC／マウスの音を解除します。

入力鍵盤は青、キャリアの基本周波数に最も近い音程はオレンジです。同じ鍵に重なった場合は青い鍵の下部がオレンジになります。表に根音がない鍵は暗く表示し、押しても入力表示だけで発音しません。鍵盤にはC−1～B9を表示します（MIDI機器の入力範囲は0～127）。

**音程表示について：** オレンジの表示はIndependent OPM 0.13の式で4MHz時の基本周波数を計算したものです。FM変調で生じる側帯波、LFOの瞬間的な変化、実機の測定結果は含みません。画面には各キャリアの周波数と最寄り音程からのセント差も表示します。

**4MHz用の表：** X68000の4MHzクロック用に補正された同梱の表を使用しています。C4 MajorはKC=0x06、KF=0x3Cで、同梱DLLの計算上は260.74／329.95／391.11Hz（C4／E4／G4）です。近似誤差は残ります。

## MIDI入力

MIDI inputのコンボボックスでデバイスを選びます。MIDIチャンネル1～8がFM1～8に直接対応します。同じMIDIチャンネルへ次のNote Onが来ると前のコードを置き換えます。これは1 MIDIチャンネル＝1 FMチャンネルの対応であり、MIDIチャンネル内の和音を複数FMチャンネルへ自動展開する方式ではありません。

MIDIチャンネル9～16も入力表示しますが、対応するFMチャンネルがないため発音しません。範囲外の音程も表示のみです。Note Onのvelocity=0、Note Off、サステインCC64、All Sound Off CC120、All Notes Off CC123に対応しています。ベロシティはキャリアTLへ反映します。MIDIで使用するチャンネルにPC入力の音があれば、MIDI入力がそのチャンネルを使用します。元のPCキーを離しても新しいMIDI音は消えません。

デバイス切り替え時はMIDI由来の発音を解除します。MIDI inputの一覧を開くたびに使用可能なデバイスを再取得します。選択していたデバイスが残っていれば表示を保持し、消えていればNoneへ戻してMIDI入力を解除します。EscまたはAll notes offで全発音を解除できます。

## 出力

- Independent OPM：同梱の`independent_opm.dll`（x64）。44.1kHz／16bitステレオでWindows既定の出力へ送ります。
- X68Sound：32bit版`X68Sound.dll`を`bin`へ置きます。`OPMChord-X68Bridge32.exe`がDLLを呼び出すため、本体が64bitでも使用できます。DLL内部は44.1kHz、補助プロセスは62.5kHzの時間軸で生成要求を受け、DLLの44.1kHz出力を変換して本体へ渡します。この部分はIndependentMDX 0.25の出力アダプターを再利用しています。
- C86CTL：64bit版`c86ctl.dll`を`bin`へ置きます。最初に検出したYM2151／OPMを選択し、GIMIC対応時は4MHzを指定します。音声は実機の端子から出力します。終了・切り替え時は実機をリセットします。

X68Sound.dllとC86CTL.dllは同梱していません。出力切り替え時は発音を解除します。読み込み失敗はダイアログと`error.log`へ記録します。失敗した場合は利用できる出力を選択し直してください。

## VS2022でビルド

Visual Studio 2022の「C++によるデスクトップ開発」とWindows SDKを導入し、`build_vs2022.bat`を実行します。本体x64、コアテスト、補助プロセスx86を順にビルドします。vswhere.exeは使用しません。

独自のインストール先の場合、コマンドプロンプトで次のように指定します。

```bat
set "OPMCHORD_VCVARS=D:\VS2022\VC\Auxiliary\Build\vcvarsall.bat"
build_vs2022.bat
```

CMakeも利用できます。x64構成で本体、Win32構成で補助プロセスを作り、同じフォルダに置いてください。

```bat
cmake -S . -B build64 -G "Visual Studio 17 2022" -A x64
cmake --build build64 --config Release
ctest --test-dir build64 -C Release --output-on-failure
cmake -S . -B build32 -G "Visual Studio 17 2022" -A Win32
cmake --build build32 --config Release
```

アプリ本体にPython・OpenCV・FFmpeg・YMFMは使用していません。データ抽出スクリプトのみPython標準ライブラリを使用します。Excelを変更して表を再生成する場合は以下を実行し、再ビルドします。

```bat
python data\extract_table.py data\YM2151_ALG_5_6_7_Code_4MHz.xlsx data
```

## Zigでクロスビルド

Zig 0.13.0を用意し、Linux等で`ZIG=/path/to/zig bash build_cross.sh`を実行します。配布EXEからデバッグ情報とビルドパスを除去するため、リンク時にstripを指定しています。
